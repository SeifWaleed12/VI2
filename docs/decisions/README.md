# Architecture Decisions

Use ADRs only for meaningful architectural decisions.

Create/update an ADR when a decision changes:
- System boundaries
- Data ownership
- Authentication strategy
- Integration ownership
- Persistence strategy
- Major infrastructure
- Major architectural patterns

Do not create ADRs for ordinary implementation details.

Each ADR should state:
- Context
- Decision
- Alternatives
- Consequences
- Scope
- Follow-up
